# Zyte 비용 절감 설계 초안

## 목표와 현재 근거

사용자는 Zyte 비용이 과도해 사용을 최대한 줄이기를 원합니다. 월별 실제 청구액과 서비스별 유료 성공 건수는 아직 조회하지 못했습니다. 비용 절감률은 추정하지 않습니다.

- 올리브영은 src/services/oliveyoung/client.ts의 zyteExtract가 직접 Zyte를 호출합니다.
- CU·세븐일레븐 등은 이미 직접 요청 후 특정 실패에만 Zyte를 사용합니다. 요청 순서 변경만으로 모든 비용을 없앨 수 없습니다.
- 기존 dailyRateLimit은 일부 공개 GET API의 클라이언트별 제한입니다. 세븐일레븐·MCP·인증된 health 경로 전체를 포괄하는 Zyte 지출 상한이 아닙니다.
- 공용 Zyte 함수에 전역 호출 예산 검사가 없습니다. 일부 호출은 기본 1회 재시도가 가능합니다.
- 올리브영에는 프로세스 메모리 기반 장애 시 이전 결과 캐시가 있습니다. API에는 Edge Cache도 있으므로 캐시를 처음 추가하는 작업으로 설명해서는 안 됩니다.
- 이번 유지보수에서 CU·디트릭스는 로컬 정상/Cloudflare 실패가 재현됐습니다. 별도 실행 위치를 검증할 근거가 있으나 다른 서버에서의 성공을 보장하지는 않습니다.

## 선택지

1. 비용 우선: Zyte 기본 차단, 직접 요청과 유효한 캐시로 서비스 가능한 범위를 유지합니다. 일부 조회 불가를 허용하며 무료 대체 경로를 순서대로 검증합니다.
2. 균형: 작은 전역/서비스별 호출 예산 내에서만 유료 fallback을 허용합니다. 한도 도달 시 직접 요청·캐시·명시적 조회 불가로 처리합니다.
3. 가용성 우선: Zyte를 유지하고 공유 캐시와 중복 요청 합치기부터 적용합니다. 절감은 가능하나 강한 비용 상한 없이는 사용량 증가 위험이 남습니다.

권장 방향은 1번 또는 2번과 직접 조회 대체를 병행하는 것입니다. 사용자가 “네 다 진행합시다”로 승인했으며 권장안인 비용 우선·Zyte 기본 차단을 구현합니다. 0회를 초과하는 유료 호출 허용 모드는 이번 범위에서 제외합니다.

## 구체 설계

### 1단계: 유료 호출 통제

requestByZyte의 실제 네트워크 호출 직전에 중앙 정책 검사를 둡니다. REST·MCP·health·재시도 모두 같은 정책을 거치며, 꺼진 상태에서는 Zyte 네트워크 요청이 0회여야 합니다. 환경변수에 키가 남아 있어도 이 정책을 우회할 수 없어야 합니다.

선택한 비용 우선 모드에서는 전송 함수가 항상 정책 오류를 반환합니다. 유료 재시도·인증·네트워크 경로를 제거하므로 원격 카운터 장애나 동시성으로 한도를 초과할 여지가 없습니다. 별도 호출 허용 모드와 예산 카운터는 구현하지 않습니다. health도 같은 정책을 따르며 서비스 실패를 정상으로 표시하지 않습니다.

### 2단계: 무료 직접 조회 확대

올리브영의 직접 요청 가능성을 먼저 검증하고 성공한 요청만 직접 경로로 전환합니다. CU·세븐일레븐·CGV 등은 현재 직접 경로와 공식 웹/앱 경로를 재현해 비교합니다. Workers에서 실패하고 사용자의 컴퓨터에서 성공하는 요청은 기존 상시 실행 가능한 장비에서 제한된 중계 서버를 시험하는 후보입니다. 새 유료 서버 계약은 이 설계에 포함하지 않습니다.

중계가 필요하면 고정된 서비스/경로만 허용하고 인증·요청 제한을 적용합니다. 임의 URL을 받아 대신 접속하는 공개 프록시로 만들지 않습니다. 운영 장비의 상시 가동 가능 여부와 외부 접근 구성을 확인한 후 구현 범위를 결정합니다.

### 3단계: 반복 조회 감소

매장·상품 목록 등 상대적으로 덜 변하는 결과의 보관 시간을 늘리고 REST/MCP가 같은 조회 결과를 공유하도록 적용 지점을 검토합니다. 동시에 들어온 같은 조회는 합칩니다. 재고·좌석은 짧은 유효 시간을 적용하고 지난 결과 제공 시 조회 시각과 오래된 상태를 표시합니다. 최신 재고로 오인되는 성공 응답을 만들지 않습니다.

## 검증

Zyte 차단 시 실제 요청 0회, REST/MCP/health 정책 일치, 병렬 호출·재시도에서도 유료 요청 0회, 실시간 재고의 신규 캐시 제외, 직접 조회 성공/실패 구분을 회귀 테스트로 확인합니다. 기존 check·coverage 100%·audit·배포 검사를 유지합니다. 운영 성공률과 Zyte 호출 수를 함께 비교합니다.

## 미결정

- 비용 우선으로 서비스 일부 저하를 허용하는 권장안을 승인받았습니다.
- 이번 유료 호출 상한은 0회이며, 유료 재허용은 후속 명시 설정 없이 발생하지 않습니다.
- 중계 서버는 후보이며 가동할 장비와 성공 가능성을 먼저 검증해야 합니다.

승인된 설계에 따라 별도 작업트리에서 구현·검증·배포합니다.
