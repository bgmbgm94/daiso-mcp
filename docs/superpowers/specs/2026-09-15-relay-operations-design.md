# 올리브영 Mac 중계 운영 설계

사용자는 전용 계정·브라우저·조회 서버·Cloudflare Tunnel·Access 구성을 승인했으며 메모리와 탭 회수 실패 방지를 추가로 요구했습니다.

## 실행 경계

기존 Worker는 Access 서비스 토큰과 중계 Bearer 토큰으로 고정된 중계 주소를 호출합니다. localhost:4319만 Tunnel에 연결합니다. 임의 URL, 브라우저 디버깅 포트, SSH, 개인 파일은 터널 대상에 넣지 않습니다. 중계는 전용 표준 macOS 사용자로 실행합니다. 계정 생성·GUI 로그인에 필요한 관리자 인증은 사용자가 직접 수행하며 비밀번호를 요청하거나 기록하지 않습니다.

## 자원 수명

브라우저 1개·컨텍스트 1개·기본 페이지 1개를 유지합니다. 요청별 새 탭을 만들지 않습니다. 예기치 않은 팝업은 닫고 닫기 실패 시 세션을 폐기합니다. 브라우저 종료를 확인하기 전에는 후속 브라우저를 실행하지 않습니다. launch 실패·요청 timeout·페이지 crash·SIGTERM·재시작에도 소유한 프로세스만 회수합니다. 개인 브라우저를 이름으로 일괄 종료하지 않습니다.

세션은 최대 30분 또는 200회 조회 후 유휴 경계에서 교체합니다. 15초 요청 제한에 더해 Node 측 watchdog으로 브라우저 이벤트 루프 정지도 감지합니다. 종료 timeout에는 소유 프로세스에만 강제 종료를 적용하고 확인이 불가능하면 fail-closed로 중지합니다. 30초 주기의 전체 소유 프로세스 RSS 점검으로 1GiB 초과 시 회수합니다. Node에도 256MiB heap 상한을 둡니다. 이 값은 운영 초깃값이며 무누수를 보증하는 수치가 아닙니다.

## 입력·부하·비밀

기존 고정 네 API·필드 타입·16KiB 검증을 유지합니다. 실행·대기 합계 8개, 직렬 실행을 유지합니다. 중계 전체에 분당 30회·UTC 하루 3,000회 상한을 적용하고 파일에 원자적으로 저장해 재시작으로 초기화되지 않게 합니다. 저장 실패·손상은 요청 거절로 처리합니다. 큐 슬롯은 본문 읽기 전 확보하여 느린 업로드도 제한합니다. 원본 JSON 응답은 최대 2MiB로 제한합니다.

토큰과 사용자 검색어·좌표·원본 응답은 로그에 남기지 않습니다. 운영 로그는 상태·건수·RSS·탭 수·재시작 사유만 기록하며 크기를 제한합니다. 토큰은 Worker secrets와 전용 계정 읽기 권한의 파일에 보관합니다.

## 배포·검증

새 기능은 TDD·100% coverage·check·build·audit와 독립 리뷰를 거칩니다. 실제 브라우저에서 반복 조회, 강제 팝업, timeout, 순차 교체, SIGTERM 및 재기동을 검증하고 브라우저/탭/프로세스 수와 RSS를 기록합니다. Access 무인증 차단, 잘못된 Bearer 차단, MCP 실제 조회까지 확인합니다. GUI 계정 준비 전에는 개인 계정으로 상시 공개 중계를 대신 실행하지 않습니다.
